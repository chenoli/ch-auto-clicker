# CH Auto Clicker — Implementation backlog (v0.1)

References: `docs/ARCHITECTURE.md` (sections cited as §N) and the design handoff (screens cited as "Screen 01.A" and so on). Quoted UI labels are the pt-BR prototype strings, which are also the i18n source.

**Conventions**

- Each task is small, can be built on its own once its dependencies are done, and delivers something verifiable.
- **Every UI task** has an implicit criterion: **visual parity with the prototype** in the Grafite theme, checked by the screen's Playwright test on the `dev/gallery` route (§9.4), with every string coming from i18n.
- **Every Rust task** closes with `cargo fmt`, `clippy -D warnings` and new tests passing. **Every TS task** closes with eslint, tsc and vitest.
- `[D#]` points to a decision made in §10.5. If the decision changes, the task is adjusted.

## Critical path and milestones

1. **M1 — Clicks precisely** (phases 0–2): engine and scheduler measured by the benchmark, no final UI.
2. **M2 — Usable in Click mode** (phases 3–4): main window with the Click tab, variation, countdown, timer and hotkeys.
3. **M3 — Three modes** (phases 5–7): multi click, wiggle and scan with overlays.
4. **M4 — Product** (phases 8–11): profiles, themes, languages, tray and HUD.
5. **M5 — Distributable** (phases 12–13): signed installer with auto-update.

Phases 9 and 10 can run in parallel with 5–8, because the token and i18n infrastructure exists since phase 0.
